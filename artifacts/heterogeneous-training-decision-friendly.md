# 异构训练是否值得：先定义“胜过谁”

本文件解释[2026-10-19 文献与立项原稿](heterogeneous-training-decision.md)。文献判断是当时检索结论，当前实验状态另见[实测选择](experiment-conclusions-friendly.md)和[取消说明](16card-experiments/cancellation-20261025-friendly.md)。

用户的强目标是：H20×8＋910B4×8 在相同模型、数据、训练预算和质量要求下，胜过 H20×16 与 NPU×16 两者中的更快方案。能同时利用两种资源，或者胜过其中较慢者，都不足以满足这个目标。

## 为什么两种卡不自动相加成优势

先看一个简化模型。若每张 H20 和 NPU 对同一种工作分别有速率 \(r_H,r_N\)，假设完全线性扩展、没有通信、训练规则一致：

\[
R_{\mathrm{mix}}=8r_H+8r_N\le16\max(r_H,r_N)=R_{\mathrm{best}}.
\]

这只是明确假设下的算术，不是实际硬件预测。现实中内存、重计算和网络会破坏线性扩展，混合才可能出现额外收益；需要测出具体瓶颈，不能从“设备不同”推出优势。

双训练副本都做相同前向、反向和 Adam 更新，没有把阶段特长分开；较慢组和 CPU 中转还可能让另一组等待。Local SGD 减少交流，但同构也可以采用同样算法，不能把算法收益归给异构芯片。

## 不同阶段才有互补空间

若实测某设备擅长生成、另一设备擅长参数更新，分工有可能有利。粗略时间模型为：

\[
T_{\mathrm{mix}}\approx\max(T_{\mathrm{generate}},T_{\mathrm{update}})
+T_{\mathrm{未隐藏发布与等待}}.
\]

只有它低于两种调优同构的最小端到端时间，且质量符合门槛，才算胜出。完整权重物化、CPU 拷贝、校验、发送和加载都应计入；不能把生成 token/s 和监督 token/s 直接取最小值当成流水线性能。

冻结教师不回传权重，适合离线数据生产，但不同于动态策略 RL。本项目实际测的是生成答案的 CE 更新，未完成奖励、KL、importance correction 等完整 RL 环节。

## 文献支持什么，不支持什么

| 研究路线 | 提供的依据 | 与当前强目标的距离 |
|---|---|---|
| H2、HETHUB、FlashFlex、HAP | 异构并行规划、负载均衡与容量互补 | 芯片、网络、规模和基线不同；含未胜过更强同构的情况 |
| DiLoCo、EDiT | 减少跨组交流的训练算法 | 优化轨迹变化，同构也可使用 |
| AReaL-Hex、StreamRL、AReaL | 生成与训练分工、异步调度 | 一些主要比较按费用，而非固定卡数；无本项目直接同条件结果 |
| CadenceRL | 重塑异构 rollout 工作负载的研究 | 硬件与 trainer 范围仍需对应核对 |

论文作者结果可以支持“某机制值得小规模试验”，不能替代 H20 / 910B4 本地三组测量。原稿逐篇保存章节、表格、反例和来源，不将作者主张写成本项目已建立机制。

## 五种收益不能混说

| 所问收益 | 需要的证据 |
|---|---|
| 同数据预算质量更高 | 固定评测与多个 seed |
| 同质量更快 | 预先固定门槛、完整质量曲线与时间 |
| 同时间质量更高 | 固定起点、任务和运行时长 |
| 同费用更好 | 实际单价、资源时、同质量工作量 |
| 可用资源池更快交付 | 可审计排队与执行；不能代替固定卡数性能 |

原立项规则要求三臂给予相同调参预算，先真实预验，再在同质量且至少约 10% 收益时考虑扩展。这个数字是原设定门槛，不是已得到的提升。

历史 4＋4 未建立较快同构之上的稳定收益；H20×16 后来证明布局本身能缓解 Socket 损失；新版 NPU×16 和混合 8＋8 已取消。因此当前三组强目标仍未闭合，不按原双副本周期平均直接扩大项目。
