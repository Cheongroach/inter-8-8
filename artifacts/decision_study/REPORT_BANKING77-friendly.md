# Banking77：准确率提高了，概率为什么还要单独检查

逐步学习入口：[模型篇](../一步步认识Jev-Laya项目-friendly.md)，第二到第七阶段分别讲预算、分类头、组合和重排。

本轮实际数据：2026-10-25。完整原始表、token 记录与错误列表保留在[技术报告](REPORT_BANKING77.md)。

Banking77 有 77 类银行业务意图，例如余额未更新、转账未到账、充值失败。实验问两个问题：增加候选描述预算能否帮助 Laya；给它领域标签训练小分类头，能否超过简单监督基线。

![Banking77 六种路径与配对提升](../figures/banking77-friendly.png)

图中监督融合与词法基线使用相同领域训练数据。右图横线是 2,000 次配对样本重采样的 95% 区间；它只反映本次测试案例的不确定性，不覆盖训练种子或分布变化。

## 数据怎样隔离

官方源有 10,003 条训练、3,080 条测试。按规范化全文去重后，训练排除 4 条；测试排除 8 条，其中 7 条与训练重复、1 条为测试内部重复；没有标签冲突。训练剩余 9,999 条中，每类固定取 10 条验证，共 770 条，其余 9,229 条拟合。去重后的 3,072 条测试只在验证选择锁写入后评价。

因此 91.67% 是这个去重测试集的成绩，不能冒充原版 3,080 条官方完整成绩。词表、IDF、分类头、正则强度和融合权重都没有用测试标签选择。

## 每条路径做了什么

| 路径 | 如何得到答案 | 与基线的重要差别 |
|---|---|---|
| 默认 Laya | 把输入与 77 类描述一起送进原模型 | 不使用本轮领域标签 |
| 扩大候选预算 | `max_len` 512 → 1024，`head_max_len` 192 → 768 | 同样权重，允许更完整的候选描述 |
| 词法监督分类器 | word / char TF-IDF＋多类逻辑回归 | 学习词和字符片段对业务类别的关联 |
| 冻结 Encoder＋分类头 | Laya 文本向量＋多类逻辑回归 | 不更新 Encoder，只学习新的 77 类线性头 |
| 概率融合 | 75% 词法概率＋25% 稠密概率 | 验证集选定的最终方案 |
| top-10 纯重排 | 监督融合先选十个候选，原 Laya 再选 | 候选以原类别顺序送入；没有强插正确标签 |

词法头的验证选择为 C16，稠密头为 C100。C 是逻辑回归正则强度的倒数，较大 C 表示较弱正则，并不是准确率阈值。原 Encoder 和 typed decision head 均未微调，所以这是一套固定业务分类适配，不是通用 Laya 模型升级。

另测两种“带先验的重排”，对候选 \(k\) 使用：

\[
s_k=\log p_{\mathrm{classifier}}(k)+\alpha z_k/T_{10},
\qquad p_k=\mathrm{softmax}(s)_k.
\]

这里 \(z_k\) 是 Laya 分数，\(T_{10}\) 是十候选运行时温度，α 为 0.25 或 1；候选外概率置零。α 越大，Laya 对原分类器分布的改动越强。漏召回仍计作系统错误，NLL 的零概率惩罚也保留。

## 看完整结果，不能只挑一个分数

| 方法 | 准确率 ↑ | NLL ↓ | Brier 求和 ↓ | ECE15 ↓ |
|---|---:|---:|---:|---:|
| 默认 Laya | 45.08% | 4.3379 | 0.8832 | 0.3537 |
| 扩大预算 | 57.00% | 3.2423 | 0.7077 | 0.2743 |
| 词法监督 | 90.82% | 0.4145 | 0.1564 | 0.1026 |
| 冻结 Encoder＋头 | 82.42% | 0.7610 | 0.2922 | 0.1519 |
| 融合（验证选定） | 91.67% | 0.4438 | 0.1639 | 0.1550 |
| top-10 纯重排 | 67.25% | 1.3474 | 0.4891 | 0.1414 |
| 带先验 α=0.25 | 91.57% | 0.3775 | 0.1316 | 0.0462 |
| 带先验 α=1 | 83.59% | 0.6881 | 0.2525 | 0.0828 |

融合相对词法为 44 胜 / 18 负，净多答对 26 条，提升 0.8464 个百分点，配对 95% 区间 [+0.3581,+1.3346] pp。相对默认 Laya 为 1,481 胜 / 50 负，提升 46.58 pp；但前者用了领域标签，后者没用，不能解释成等训练信息的模型排名。

准确率只关心概率最大的选项；NLL 关心给真实类别的概率，Brier 关心整个分布，ECE 比较置信度和实际正确率。融合能在少量边界案例中换成正确选项，同时让概率分布整体更不适合当前评分。表中三个概率指标都变差，因此不能直接拿融合概率设置业务自动接受阈值。[公式与例子](../METRICS.md)解释了这一区别。

α=0.25 的测试概率指标更好，但其验证准确率未胜过融合，所以协议没有选择它。披露所有结果不等于允许事后改选。

## 候选预算到底影响了什么

默认配置每个选项仅有 4 token 表示，77 类变成 73 种不同表示。扩大预算后恢复 77 种；top-10 则有 10 种不同表示。测试全部路径均无报告的 state 截断，所以这里的“折叠”指不同候选得到相同 token 表示，并非测试正文被截断。

top-10 测试召回为 99.707%，即 3,063 / 3,072 条包含正确类别。但纯重排只答对约三分之二。候选遗漏不足以解释全部错误；本轮固定模型和描述下，重排本身仍是限制。这个结果不能推广为所有 Laya checkpoint、语言和任务的能力上限。

原 checkpoint 的 `choice:11+` 温度约 0.10058，固定上游运行时把它钳制到 0.5。本报告使用实际运行时温度计算概率，不把配置原值当成实际输出。

## 时间、回放与剩余错误

默认、扩大预算、top-10 的测试决策阶段分别为 1,687.89、1,285.12、256.49 秒。都是共享 CPU、FP32、8 线程、batch 8，含编码、forward 和落盘，排除加载；top-10 还排除了候选分类器时间。没有重复计时证明扩大预算更快，这些值不能当完整 API 延迟或 GPU 加速比。

初次内部 forward 缺少公共 API 提供的 inference context，在产生验证预测前中断。恢复保存分类头后，验证指标逐项一致；原代码快照、协议哈希与恢复说明保留。八种测试指标已从完整概率复算；16 例公共 API 回放选择全一致，最大概率差低于 3.3e-6。回放不是新增测试样本。

剩余错误包含“余额未更新”与“收款人未收到转账”、充值 pending / failed / reverted、实体卡 / 虚拟卡操作等相近类别。它们是看完测试后的描述性诊断，没有用于重新拟合。本轮没有 Jev、强微调分类器或生成模型同条件对照，不能称 SOTA；上游称 Banking77 非训练内任务，也不等于本项目独立审计过全部预训练数据。
