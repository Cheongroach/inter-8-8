# 第一轮协议：怎样避免“看完测试才挑赢家”

这是 2026-10-25 第一轮冻结协议的阅读说明。[原协议](PROTOCOL.md)保留不动，结果见[三轮报告](REPORT.md)。

第一轮想知道：已有 Laya 新闻分类概率能否通过少量数据校准；同一组选项换顺序会不会改答案。校准只调整输出分数，不更新原 Encoder。

## 三份数据各做一件事

AG News 有四个新闻类别。原训练源 120,000 条、测试源 7,600 条；本次训练下载截断，在任何推理前固定只用前 20,000 条完整训练行，测试源则验证完整 Git blob。不能把前缀当成完整训练来源。

规范化全文去重，训练源优先，禁止重复跨集合。按 `SHA256("20261025:" + source_row_id)` 排序，从训练前缀取 128 条拟合、后 128 条验证；从测试源取 256 条保留测试。拟合集学参数，验证集选配置，保留集只评分。哈希排序让划分可以重做，不能消除同事件相关性或预训练污染。

数据副本固定为 `mhjabreel/CharCnn_Keras` 的提交 `555590db4219b1243abb1918effd6a7425a2d75f`。Laya 源码和英文权重分别固定为 `7a77439b0923d6efe00052d50a7f787840bfce98`、`7b928d828b7b0e022f929d9bd2e44165aa270148`。实际输入 SHA256、样本 ID、代码指纹在预测前写入 `protocol.json`。

## 七个候选为什么要提前写下

| 候选 | 调整什么 | 成本 / 约束 |
|---|---|---|
| 自带温度 | 使用 checkpoint 的 `choice:3-5` 温度 | 原模型概率基线 |
| 新温度 | 在 0.25–16 的 161 个对数等距值中拟合 | 不改变最大分数对应选项 |
| 三种仿射 | 4×4 矩阵＋4 个偏置；正则 0.01 / 0.1 / 1 | 共 20 参数；400 次优化、学习率 0.01 |
| 两种排列集成 | 四种循环排列的概率均值；自带 / 新温度 | 四倍 forward，不是等延迟优化 |

仿射映射 \(Az+b\) 正则到单位矩阵和零偏置。这里直接作用于原始 logits，因此零更新先验对应温度 1，而不是 checkpoint 的原校准分布。这一差别在第二轮被显式调整。

每条输入执行四种循环排列，输出恢复原类别顺序后存未经舍入的 logits。所有路径保持同一问题、类描述、权重和 CPU eager（直接执行 PyTorch 算子）环境，batch 8、8 个 Torch 线程。

验证选择依次比较准确率、NLL、较少 forward、配置名；测试必须披露全部七配置，禁止按测试换赢家。第一轮最终选择仿射 1.0，但概率指标退化，作为有效负结果保留。

## 怎样评价

报告准确率、NLL、Brier 求和、15 等宽桶 ECE、平均最大概率，以及原排列与循环移位两位的选择翻转率。主比较为验证赢家与原模型在同一 256 条保留样本上的差值；配对 bootstrap 2,000 次，seed 20261025，报告胜 / 负和 95% 区间。[指标说明](../METRICS.md)给出完整分母与公式。

时间含分词、拼接、forward、解码，排除下载与加载。CPU 离线时间不能作为 H20 速度或 Jev 托管 API 延迟。

## 复现入口

从项目根目录运行，使用新的输出目录，避免覆盖原证据：

```bash
python laya/decision_study/evaluate.py \
  --upstream /path/to/pinned/laya-checkout \
  --model /path/to/pinned/laya-checkpoint \
  --data /path/to/ag_news_csv \
  --output /path/to/new-round1
```

`prepare_data.py` 默认验证完整源文件再导出训练前缀；本轮显式使用 `--allow-training-prefix-only`，但完整测试文件仍须校验。已有输入重复导出逐字节一致。Jev 入口读取环境中的 `TYPESAFE_API_KEY`，固定 `jev-1.14.0`；本轮记录 `not_run`、`api_calls=0`，没有 API 质量分数。

上游将 AG News 标为训练内任务，本轮只评价该分布内的决策与校准。多个种子、独立领域、真实拒答和服务成本仍未覆盖。下一轮另设数据和协议，见[第二轮说明](PROTOCOL_ROUND2-friendly.md)。
