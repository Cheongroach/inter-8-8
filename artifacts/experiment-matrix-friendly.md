# 4＋4 实验设计：每个对照想排除什么

这是[历史矩阵](experiment-matrix.md)的解释。用户先将目标放宽为小规模实测：各四卡混合，对照两种同构八卡，再决定是否值得扩规模。

模型为 Qwen2.5-7B-Instruct 和 Qwen3.5-4B 文本主干；后一模型不训练视觉或 MTP。输入为固定 GSM8K 问题和答案，权重文件逐个锁定 SHA256。

| 实验因素 | 控制什么 | 为什么需要 |
|---|---|---|
| 各设备四卡 profile | batch 1 / 4 / 8 生成，输出上限 64 / 128；训练 microbatch 1 / 2 / 4 | 看生成和反向的优势是否在两种卡间交叉 |
| 混合逐步同步 | H:N microbatch 2:2、3:1、1:3；全局 16 样本 / 更新 | 看负载配比能否减少等待 |
| 每 4 / 8 步参数平均 | 各组先本地 AdamW，再交换参数 | 看减少交流能节省多少；同时承认轨迹改变 |
| 两种分工方向 | H20 生成 / NPU 训练，以及反向 | 不预设硬件排序 |
| 顺序 / 重叠、间隔 1 / 2 / 4 | 控制刷新频率与执行顺序 | 区分发布成本和可能隐藏的等待 |
| 固定教师、分块发布 | 不刷新权重 / 改变发布实现 | 看完整参数回传和 CPU 打包的代价 |
| H20×8、NPU×8 | 相同数据与策略的同构对照 | 防止只比“混合能跑”，不比最佳同构 |

训练用 FP32 master 和 AdamW、BF16 计算、岛内 FP32 梯度归约。跨岛必须交换同一逻辑参数区间，不能只因两侧 rank 编号相同就默认分片正确。

生成 / 更新分工用实际生成答案做交叉熵 CE，校验参数名称、形状、版本和 SHA256。它没有强化学习所需的奖励或 importance ratio，不能称完整 PPO / GRPO。

比较同时看实际样本 / token / EOS、最慢 rank 墙钟、拷贝与发布、资源时、更新规则及共同 kernel。成功 precheck 只允许提交；成功运行仍不代表质量或性能获胜。

矩阵已执行，结果见[结论说明](experiment-conclusions-friendly.md)、[完整组合](combination-comparison.md)。新版 16 卡另见[矩阵说明](16card-experiments/new-architecture-matrix-friendly.md)，不要把两个规模混成同一计时对照。
