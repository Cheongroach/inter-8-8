# 组合表格怎样读：先找同一工作，再比较时间

本文件解释[完整原表](combination-comparison.md)。原表保留所有组合，空白表示没有完成证据，不能当作零耗时。

Qwen2.5-7B 在表中简称 `q25`，Qwen3.5-4B 文本主干简称 `q35`；H / N 分别指 H20 / 910B4。同构是只用一类卡，混合是各 4 卡。

## 训练表比较什么

每 case 8 个更新、全局每步 16 样本。`sync-equal` 为两岛 microbatch 2:2，`h3-n1` / `h1-n3` 改为 3:1 / 1:3，仍保持全局样本数；`local-h4` / `local-h8` 分别每 4 / 8 步平均参数。

| 模型 | 最低频混合，秒 | 更快同构，秒 | 混合 / 更快同构 |
|---|---:|---:|---:|
| q25 | 63.36 | 14.16，H20×8 | 4.47×，更慢 |
| q35 | 24.58 | 18.70，NPU×8 | 1.31×，更慢 |

原表“相对更快同构”是时间比值 \(T_{\mathrm{mix}}/\min(T_H,T_N)\)，大于 1 表示更慢，不是加速倍数。

取两岛各自累计 step 时间的较大值，含等待、拷贝和交换，排除 case 间加载、评测、日志。参数平均保留独立 AdamW 状态，改变轨迹；没有同质量证明。

## 分工表中的字段

| 字段 | 含义 |
|---|---|
| `H生成/N训练` | H20 出答案，910B4 用答案更新 |
| `pipeline` / `pipeline-buckets` | 逐参数 / CPU 分块发布；不同实现需分别比较 |
| `serial` / `overlap` | 顺序执行 / 尝试重叠生成与训练 |
| 间隔 1 / 2 / 4 | 每几个更新刷新生成权重 |
| `frozen`、间隔 0 | 固定教师，只传轨迹，不回传权重 |
| 监督 token/s | 实际监督 token 总数除以全部 rank 最慢时间 |

每 case 4 个更新、每生成卡 batch 2、输出最多 128 token；总时间含最后发布。部分 case 实际监督 token 略少，必须使用对应行分母，不能只比较 token/s 而忽略生成长度。

同一逐参数、overlap、间隔 4 下，q25 较好混合 68.16 秒，H20 同构 64.73；q35 较好混合 44.24，NPU 同构 40.70。只胜过较慢同构不满足“胜过最佳同构”的目标。

间隔 1 每步仍等待发布，不能把 `overlap` 字样当成真实跨步重叠证据。固定教师改变行为模型；短程 CE 不是完整 PPO / GRPO。每配置仅一次短程观测，几个百分点的差距未建立稳定统计排序。

原表共有 10 个训练组合、73 个分工 case，分工要求八个 rank 的完成事件。最终选择与测量边界见[结论说明](experiment-conclusions-friendly.md)；[机读指标](combination-metrics.json)及[rank 日志](experiment-results/)支持逐项追溯。
