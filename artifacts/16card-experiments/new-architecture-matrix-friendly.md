# 新模型对照矩阵：计划测什么，实际完成什么

这是[2026-10-19 原矩阵](new-architecture-matrix.md)的阅读版本，状态更新到 10 月 25 日。原稿里的“尚无 16 卡性能”是提交时状态，不是最终状态。

目标是比较同一总卡数下的三组：H20×16、910B4×16、H20×8＋910B4×8。NPU 是昇腾设备；两个不同设备后端组成混合组。每组还要比较通信和分片策略，避免只拿未经调优的同构作为基线。

## 为什么换模型

| 模型 | 文本主干参数 | 层数；DeltaNet / 完整注意力 | 用途 |
|---|---:|---|---|
| Qwen3.5-4B | 4,205,751,296 | 32；24 / 8 | 小规模校验 |
| Qwen3.5-9B | 8,953,803,264 | 32；24 / 8 | 主对照 |
| Qwen3.8-27B | 26,895,998,464 | 64；48 / 16 | 大模型边界 |

这是配置构建 meta 模型得到的文本参数数，不包含视觉 / MTP。3.8 官方模型卡说明它沿用 3.5 架构基础，不能按版本名字称为一种完全独立架构。Qwen2.5 结果作为历史数据保留。

## 每个实验因素有什么作用

全局 FSDP16 把分片放到所有卡；HSDP 2×8 把分片留在每台机器内，机间复制并同步梯度。两者可保留同步训练语义。CPU/TCP 每步梯度交换检查主机中转代价；每 4 / 16 步参数平均减少通信，但保留本岛 Adam 状态，改变优化轨迹，不是完整 DiLoCo。

CUDA 原生路径比较 RDMA 与强制 Socket。NPU 无机间 RDMA 场景采用机内 HCCL、机间 CPU/TCP，并非已验证“关闭原生 HCCL RDMA”。生成 / 更新分工使用实际回答的 CE 更新，没有 PPO / GRPO 奖励或 KL。

同模型各配置保持相同数据和更新次数；27B microbatch=1，另外两个为 2，因此 global batch 为 16 / 32。共同采用 BF16 计算、FP32 master 和 AdamW。

## 实际覆盖

| 实验臂 | 截至 10 月 25 日 | 已有结果 |
|---|---|---|
| H20×16 | 完成，两个物理 host、两个 pod 退出 0 | 3 模型×7 配置×2 次计时；9 个生成 / 更新 case |
| 910B4×16 | 确认 stopped / killed | 无新版主对照结果 |
| 新版混合 8＋8 | 确认 stopped / killed | 无新版 9B / 27B 主对照结果 |

不能把终态或 CPU 小模型前后向通过当成完整 NPU 训练结果。9B / 27B 权重哈希与官方文件清单一致，仍不能代替 3.8 兼容实现的输出 / 梯度参考校验。

27B 先 CPU BF16 加载、逐层转 FP32 并分片，解决分片前初始化容量问题。训练按聊天文本边界分别分词，避免把文本前缀误当作 token 前缀。它们是运行契约，不是模型质量收益。

结果与解释见[H20 图解报告](paper/report-friendly.md)；不可变[模型清单](new-model-manifest.json)、[代码指纹](code-sha256.json)可追溯，终态见[取消说明](cancellation-20261025-friendly.md)。来源：[Qwen3.8 模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)、[Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)。
