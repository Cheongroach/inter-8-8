# 怎样读质量、速度与通信指标

先确定问题：选择有没有做对，用准确率；概率能否用于风险阈值，用概率评分和校准；训练能否更快交付可用模型，用达到同一质量所需时间。这些指标不能互相代替。

## 选对答案，与给对概率

设有 \(n\) 条测试输入、\(K\) 个允许类别。第 \(i\) 条真实类别是 \(y_i\)，模型给类别 \(k\) 的概率是 \(p_{ik}\)，最大概率对应的预测是 \(\hat y_i\)。

| 指标 | 定义 / 直觉 | 怎样比较 |
|---|---|---|
| Accuracy，准确率 | \(\frac1n\sum_i \mathbf1[\hat y_i=y_i]\) | 越高越好；只看最终选择 |
| NLL，负对数似然 | \(-\frac1n\sum_i\log\max(p_{i,y_i},10^{-12})\) | 越低越好；高置信度答错会受重罚；本项目用自然对数 |
| 多类 Brier 求和 | \(\frac1n\sum_i\sum_{k=1}^K(p_{ik}-\mathbf1[y_i=k])^2\) | 越低越好；本项目不再除以类别数 |
| ECE15，校准误差 | 按最大概率分成 15 个等宽桶，比较每桶平均概率与实际准确率 | 越低表示本次分桶下的差距越小；依赖分桶，不能独立证明概率可靠 |
| top-10 recall，候选召回 | 正确类别是否进入前 10 个候选 | 是最终准确率的上限；进入候选仍可能被选错 |

ECE 的完整口径为：

\[
\mathrm{ECE}_{15}=\sum_{b=1}^{15}\frac{|B_b|}{n}
\left|\frac{\sum_{i\in B_b}\mathbf1[\hat y_i=y_i]}{|B_b|}
-\frac{\sum_{i\in B_b}\max_k p_{ik}}{|B_b|}\right|.
\]

空桶不计。\(B_b\) 是最大类别概率落入第 \(b\) 个区间的样本集合。

一个最小例子：真实答案是 A，两个模型都选 B；若给 A 的概率分别为 0.4 和 0.01，准确率都为零，NLL 却分别约为 0.916 和 4.605。第二个模型更坚信错误答案，因此受到更大惩罚。也可能两模型选项相同，只是概率变柔和，此时准确率不变而 NLL 改善。

温度缩放用 \(p_k=\mathrm{softmax}(z_k/T)\)。\(z_k\) 是未经归一化的类别分数，\(T>0\) 是在独立数据上拟合的温度。增大 \(T\) 使分布更平缓；正温度不改变最大分数位置，所以不会改变准确率。

## 百分点与配对区间

91.67% 减 90.82% 约为 **0.85 个百分点（pp）**，不是提高 0.85% 的相对比例。Banking77 精确差值为 \(26/3072\times100=0.8464\) pp。

配对比较把同一条输入的两个预测放在一起：新方案对、基线错为“胜”，反之为“负”。本轮 44 胜、18 负，因此净多答对 26 条。配对 bootstrap 每次重采样同一组输入索引，并保留两方案的对应关系；2,000 次差值的分位数给出本项目报告的 95% 区间。

这个区间只反映本次测试样本重采样。它没有覆盖重新训练、重新划分、新闻事件相关性或未来分布变化。两次训练计时的黑点是两次原始观测，也不是这种区间。

## 训练速度的分母

“更新”是一次优化器修改参数；microbatch 是单卡单次前向/反向处理的样本数；global batch 是一次更新实际覆盖的全局样本数，包含梯度累积。

\[
\mathrm{监督token/s}=\frac{\text{本次更新使用的有效监督 token 总数}}{\text{执行段耗时}},
\qquad
\mathrm{card\!-\!seconds}=\text{卡数}\times\text{执行段秒数}.
\]

监督 token 是参与损失计算的答案位置，不能把所有 prompt token 都算进去。分布式中同一份全局数据不能按 rank 重复累计。

墙钟时间是从开始到结束的实际经过时间。所有 rank 必须完成的任务，应取最慢 rank 的时间。H20×16 本项目含数据准备、更新、等待与最终交换，排除模型加载和排队。历史 4＋4 的累计 step 时间还排除了部分日志与评测，因此两种口径不能直接拼接。

“同质量时间”要求先固定质量门槛，例如准确率和 NLL 均满足要求，再记录首次达到门槛的时间。只运行 16 个更新、只看到 loss 下降，不能得到同质量加速结论。卡秒也不是账单；费用还需要价格和计费范围。

## 设备如何协作

| 术语 | 直觉 | 主要代价 |
|---|---|---|
| FSDP，全分片数据并行 | 不同卡只常驻部分参数 / 状态，计算某层时临时凑齐所需参数 | 参数收集和梯度分发频繁 |
| HSDP，混合分片数据并行 | 一台机器内分片，不同机器保存对应副本 | 把参数物化留在机内；机间仍同步梯度 |
| NCCL / HCCL | CUDA GPU / 昇腾 NPU 各自常用的集合通信库 | 标准路径不提供混合设备的直接 collective |
| Gloo / TCP | 主机 CPU 张量聚合 / 字节传输 | 设备搬运、CPU 缓冲、网络和写回 |
| RDMA | 本次 NCCL 日志确认使用的网络数据通道，可减少主机中转开销 | 必须检查实际通道，设备可见不足以证明使用 |
| Socket | 本项目强制 NCCL 使用的普通网络传输路径 | 与 CPU/Gloo 算法路径不同 |
| Local SGD / 参数平均 | 各组先本地训练 \(H\) 步，再平均参数 | 减少交流，也改变优化轨迹 |
| DiLoCo | 局部优化＋外部更新的低通信方法 | 有自己的外部优化器；本项目简单参数平均不是完整 DiLoCo |

参数平均为 \(\bar\theta=\frac1m\sum_{j=1}^m\theta_j\)，其中 \(m\) 是训练组数。若每组保留独立 Adam 状态，这一般不等价于全局 batch 上的一次 AdamW 更新。\(H=16\) 且实验只有 16 步，意味着只在末尾交流一次。

“生成 / 训练分工”让一组模型产生答案，另一组用答案更新参数。固定教师始终用旧权重生成，动态生成者则定期接收新权重。本项目使用生成答案的交叉熵（CE）更新，没有 PPO / GRPO 所需的奖励、KL 或重要性校正，不能把它当成完整强化学习。

## 字节与内存

GB 是 \(10^9\) 字节，GiB 是 \(2^{30}\) 字节。FP32 每元素 4 字节，BF16 每元素 2 字节。

若采用 FP32 参数、FP32 梯度和 Adam 的两个 FP32 状态，\(P\) 个参数的基础状态约为 \(16P\) 字节。这还没有包括激活、临时完整参数、通信缓冲、CPU 快照和其他实现副本。

理想单向传输时间为 \(T=8S/B\)，\(S\) 的单位是字节，\(B\) 是 bit/s。32.8 GB 在 10 Gbit/s 上为 26.24 秒，只是满带宽、无额外成本的估算，不能当成实测同步时间。
